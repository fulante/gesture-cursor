## 1. 产品与边界

Gesture Cursor 用普通摄像头采集手部画面，由 MediaPipe 输出 21 个手部关键点，手势状态机把关键点翻译成鼠标/音量动作，再通过 PyAutoGUI 和 Windows 媒体键作用到本机。全部推理在本地完成，摄像头画面不上传。

前端展示页是另一个独立入口：浏览器内加载本地的 MediaPipe WASM 与 `hand_landmarker.task` 模型，在页面里画骨架、虚拟光标和手势反馈。浏览器没有权限移动 Windows 系统光标，因此展示页只做演示，不替代桌面程序。两端的职责不能混写。

| 能力 | 桌面程序（Python） | 前端展示页（React） |
|---|---|---|
| 摄像头采集 | OpenCV，本机摄像头 | 浏览器 `getUserMedia` |
| 手势识别 | MediaPipe 21 点 | MediaPipe Tasks Vision，本地 WASM |
| 光标/点击/拖拽/滚动 | 真实系统鼠标 | 页面内虚拟光标 |
| 音量 | Windows 媒体键 | 仅状态展示 |
| 运行位置 | Windows 宿主机 | 浏览器（localhost 或 HTTPS） |
| 数据上传 | 无 | 无 |

## 2. 架构与数据流

```text
摄像头
  └─ OpenCV 采集（640×480，可配置）
       └─ HandTracker（MediaPipe，21 个关键点）
            └─ GestureController（手势状态机）
                 ├─ MouseController（PyAutoGUI：移动/单击/双击/拖拽/右键/滚动）
                 ├─ VolumeController（Windows 音量媒体键）
                 └─ HUD（FPS、当前状态、最后动作、活动区域）
```

前端：

```text
浏览器摄像头
  └─ MediaPipe Tasks Vision（public/wasm + public/models/hand_landmarker.task）
       └─ 页面内虚拟光标与手势反馈（不调用系统鼠标）
```

关键模块：

| 模块 | 职责 |
|---|---|
| `main.py` | 主循环、摄像头打开、窗口与退出处理 |
| `config.py` | 摄像头、光标、手势阈值、时序等全部可调参数 |
| `hand_tracker.py` | MediaPipe 封装，返回 21 个像素坐标关键点 |
| `gesture_controller.py` | 手势状态机，把关键点翻译成鼠标语义 |
| `mouse_controller.py` | PyAutoGUI 封装，failsafe、滚轮单位与按键释放 |
| `volume_controller.py` | Windows 音量媒体键封装 |
| `utils.py` | FPS 统计、HUD 绘制、距离计算 |
| `frontend/` | React + Vite 展示页，独立构建、独立部署 |

手势判定使用手掌尺寸归一化、手指角度/关节比例、迟滞、边沿触发和小数累加器，避免固定像素阈值在换摄像头或改变手距后失效。具体阈值和调参说明见根目录 `README.md` 的 Configuration 一节。

## 4. 环境与安装

### 4.1 桌面程序

要求 Windows 10/11、Python 3.9–3.12（推荐 3.12），不要使用 Python 3.13，因为 `mediapipe==0.10.21` 没有 cp313 wheel。依赖固定为 `requirements.txt` + `constraints.txt`。

发布快照 `final-product/` 内置一键脚本，进入该目录后运行：

```bat
setup.bat
run.bat
```

`final-product/setup.bat` 用 `py -3.12` 在 `final-product/` 内创建 `.venv` 并按约束安装依赖；同目录的 `run.bat` 用该 `.venv` 启动快照里的 `main.py`。根目录开发版没有 `setup.bat`，按下面的手动命令在根目录创建 `.venv`，再运行根目录的 `run.bat`。如果摄像头打不开，先运行：

```bat
camera_test.bat
```

它会依次尝试 `ANY` / `DSHOW` / `MSMF` 和索引 0–5，并打印可用的 `CAMERA_INDEX` / `CAMERA_BACKEND`。当前机器上摄像头可能要求以管理员身份运行。

手动等价命令：

```bat
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt -c constraints.txt
python main.py
```

### 4.2 前端展示页

要求 Node.js 22（CI 使用 22；若停留在 Node 20，需 20.19+，否则最新 Vite 无法运行；本地验证使用 Node.js 24.20.0，构建正常）。首次安装与构建：

```bash
cd frontend
npm ci
npm run build
```

构建产物在 `frontend/dist/`，必须通过 `localhost` 或 HTTPS 提供，浏览器才允许访问摄像头。它只用于展示，不移动系统光标。

## 6. 发布与回滚

发布物只有源码快照，不含容器镜像。

| 项目 | 位置 |
|---|---|
| 当前发布版本 | `final-product/VERSION` = `1.1.5` |
| 文件校验 | `final-product/SHA256SUMS.txt` |
| 历史基线 | `legacy/`（v1.0 原始快照） |
| 变更对比 | `legacy/v1.1.diff` |
| 回滚运行 | `run_legacy.bat` |

Windows 上校验单个文件：

```powershell
Get-FileHash .\final-product\main.py -Algorithm SHA256
```

把结果与 `SHA256SUMS.txt` 中对应行比较。清单使用大写十六进制，`tests\` 路径为 Windows 分隔符。

回滚步骤：

1. 退出当前程序，确认没有按键处于按下状态（PyAutoGUI failsafe 或 `release_all()` 会释放）。
2. 运行 `run_legacy.bat`，确认 v1.0 基线可以启动并完成基本手势。
3. 记录回滚时间、版本和验证结果。
4. 需要回到新版本时，重新运行 `run.bat`；源码始终保留在 `final-product/` 与根目录。

回滚不涉及数据库、容器或服务重启，因此没有数据迁移和卷恢复步骤。

## 7. 部署方式

桌面程序是本地安装，不部署到服务器：

1. 复制整个项目目录到目标 Windows 机器；
2. 安装 Python 3.12；
3. 进入 `final-product/` 运行 `setup.bat`（或在根目录按第 4.1 节手动建 `.venv`）；
4. 运行 `camera_test.bat` 确认摄像头索引；
5. 运行对应目录的 `run.bat`，按 `q` / `Esc` 退出。

前端是静态站点：执行 `npm run build` 后，把 `frontend/dist/` 交给任意静态服务器（例如 `npx serve frontend/dist`），或部署到支持 HTTPS 的静态托管。不要把 `frontend/dist/` 当作系统控制入口。

本产品没有 Web 后端、数据库、Docker 镜像和 Agent 连接；不要按旧平台的方式配置端口、探针、令牌或容器卷。

## 9. 已知限制

- 当前实现以 Windows 为主；macOS/Linux 未做验收。
- 当前机器摄像头可能要求管理员权限。
- 未做 DPI 感知与多显示器选择。
- 端到端延迟（采集→识别→鼠标动作）尚未完整采集；现有 p50 11.3 ms / p95 12.1 ms 是 640×480、`MODEL_COMPLEXITY=1` 下的推理基准，不是端到端指标。
- 摄像头若在会话中改变分辨率，需要重启程序；光标映射使用首帧实际分辨率。
- 未做逐用户校准；主要在一台机器、一个摄像头、一名用户上验证。
- 未打包成安装程序，交付物是源码快照。
- 前端只能控制页面内虚拟光标，不能控制 Windows 系统光标。
